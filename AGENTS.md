## Project: Delta — Personal Finance Webapp

A personal finance webapp that connects to financial institutions via **Plaid** and serves the data through a dashboard. Two deliverables live in this repo:

1. **The webapp** — Plaid link flow, data sync, and a view-only dashboard. There is no in-app chat; each card has an "Ask" button that copies it as a prompt for the user's agent.
2. **Agent access** — a provider-agnostic MCP server (`/api/v1/mcp`) whose instructions and tool descriptions carry the finance conventions, analysis method and advice guidelines. It must not assume any specific LLM provider. (The markdown `delta-finance` skill, `ADVISOR.md` and the SQL fallback were retired 2026-10-31 in favor of MCP.)

## Agent advisor mode

This file is the **development** doc. Agents acting as a personal-finance advisor against a running Delta instance connect to its MCP server (README "Connect an agent"); `INSTRUCTIONS` in `lib/mcp.ts` is the source of truth for what they're told.

## Stack & Architecture

Decided 2026-07-08 (session 1). Roadmap lives in GitHub milestones/issues on `zeapsu/Delta`.

- **Stack:** Next.js (App Router, TypeScript) + Tailwind, SQLite via Drizzle (better-sqlite3). Single codebase; Plaid calls happen in API routes only.
- **Deployment:** headless Jetson (ARM Linux), 24/7, served over Tailscale to tailnet devices only. The tailnet is the trust boundary; an optional web UI password (below) is a second lock.
- **Agent:** Delta has **no agent of its own**. The user talks to their data through **Felix**, their agent in OpenBot, which reads Delta through the MCP server. The in-app chat tab was removed 2026-10-28 (it had no backend since Hermes was retired 2026-10-20; #58 is superseded). The hand-off is `app/ask-agent.tsx` (agent-agnostic, "Ask Agent" since #77): titled `Card`s and every `Page` header get an "Ask" button that copies the visible text plus page/URL/time as a ready-to-paste prompt (opt out with `<Card ask={false}>` on forms). Gotcha: Delta is plain http on the tailnet IP, so `navigator.clipboard` is unavailable (not a secure context) — the button falls back to `execCommand("copy")`. The MCP server stays provider-agnostic, usable from any agent.
- **Agent hardening:** any agent gets least-privilege access — read-only DB access by default (Plaid tokens never exposed), writes only through validated app API routes, automated SQLite backups.
- Build/test/lint commands: `npm run dev` (dev server), `npm run build` (production build), `npm run lint` (ESLint), `npm test` (the pure-logic `*-check.ts` self-checks). DB smoke test: `npx tsx db/check.ts`. E2E: `npm run build && npm run e2e` (Playwright against the production build, a fresh `e2e/.tmp` DB and a mock Plaid in `e2e/plaid-mock.mjs` enabled by `PLAID_MOCK_URL`, sandbox only; covers the v1 API, MCP via the official client SDK, every page on desktop/light, phone/dark (Chromium, Pixel 7) and iphone/light (WebKit, the engine of every iOS browser; CI installs it, locally `npx playwright install webkit`) with an axe WCAG 2.1 AA scan and screenshots in the report, the layout rules in `e2e/layout.ts` (nothing past the screen edge or out of its card, no control wider than its column, form fields ≥16px on phones; phones also run at 320 and 375px, and `STATES` in `pages.spec.ts` lists the pages plus opened forms/dialogs, so add a state when a page gains one), and the expired-login → Reconnect path via the mock's `POST /__mock/fail`; `/__mock/pending` + `/__mock/post` make a charge post). WebKit on Linux is not iOS: Safari's native controls (the date field that overflowed in #135) only render like that on a device, so a new native control type still needs a look on an iPhone. CI (`.github/workflows/ci.yml`) runs `Checks` (lint, tsc, `npm test`, again under UTC+14 and UTC-11 so UTC-only date math fails, db check, migration drift) and `E2E` on every PR; both are required on `main`. Not required: `Image smoke test` (PRs: builds the Docker image, boots it, mints a token with the bundled CLI, reads the API, runs a backup) and `audit.yml` (weekly + lockfile changes on main: `npm audit --omit=dev`). Dependabot opens weekly grouped update PRs, and `dependabot-automerge.yml` turns on squash auto-merge for patch/minor ones (merged once CI is green; majors wait for review; needs "Allow auto-merge" in repo settings), and `dependabot-update.yml` (on push to main + hourly) clicks Update branch on behind auto-merge PRs and dispatches CI there, since GITHUB_TOKEN pushes trigger no pull_request runs; `codeql.yml` skips itself while the repo is private (user-owned private repos can't use code scanning). A new page goes in `PAGES` in `e2e/pages.spec.ts`; a new MCP tool or v1 route gets a case in `e2e/mcp.spec.ts`/`api.spec.ts`.
- **DB conventions (M1):** money as integer cents (Plaid sign convention: positive = money out), timestamps as `timestamp_ms`, snake_case SQL columns / camelCase TS keys. Schema in `db/schema.ts`; after editing it run `npx drizzle-kit generate` and commit the `drizzle/` output — migrations auto-apply when `db/index.ts` is first imported at runtime (no separate migrate step on the Jetson); `next build` skips them via `NEXT_PHASE`, since parallel build workers would race on the live DB, and `instrumentation.ts` imports it at server start, so a new migration lands as soon as the restarted server boots. DB path: `DATABASE_PATH` env, default `./delta.db`.

- **Plaid conventions (M2):** client singleton in `lib/plaid.ts` (`server-only`, environment switched via `PLAID_ENV` — see Production Plaid gate); sync engine in `lib/sync.ts`. Gotcha: `/transactions/sync` returns `accounts: []` when nothing changed, so balance snapshots come from `accountsBalanceGet` (which also returns non-transaction accounts — loans/IRA etc.). No in-app scheduler by decision: the `delta-sync` systemd timer (see M6) `POST`s `/api/plaid/sync` every 6h instead, after first `POST`ing `/api/plaid/refresh` (`/transactions/refresh` on every item, free on Plaid's Trial plan, per-call on paid plans; Capital One credit-only items answer `PRODUCTS_NOT_SUPPORTED` and are skipped) and sleeping 3 min, since refresh is async and Plaid's own transaction pulls are only 1-4x/day while balances are live. **Never log (or let escape to Next.js) a raw Axios/Plaid error** — `err.config.data` is the request body with `client_id`, `secret` and `access_token`; log only `safePlaidError(err)` fields (`error_code`, `error_code_reason`, `request_id`) plus item id/institution (#60). `syncAll()` catches per item and returns `errors[]`; `/api/plaid/sync` answers 502 when any item failed so the timer's `curl -f` still fails. Each sync records `items.last_error_code` (null on success) and `last_synced_at`; `POST /api/plaid/sync` with `{"item_id": n}` syncs one connection (queued behind any run in progress, never joined to it: that run may have passed the item already). The first sync after linking goes through the same queue (`syncOne`), so it records `last_synced_at`/`last_error_code` too. Linking a bank again gives a new Plaid item and new account ids, so `/api/plaid/exchange` compares the new item's `/accounts/get` accounts with every connection's (`duplicateOf` in `lib/duplicate-link.ts`, self-check `duplicate-link-check.ts`: same institution name and a shared mask + type + subtype, name when there is no mask) and on a match removes the new item at Plaid (`/item/remove`) and answers 409 "<bank> is already connected"; other accounts at the same bank still link, and so does a bank whose connection Plaid no longer has (`GONE_ERROR_CODES`, since Reconnect can't repair that). It also saves the accounts at link time (`saveAccounts`), so that check works even when the first sync failed. E2E: the mock's `public-sandbox-mock-again` public token is the same bank linked twice, and `POST /__mock/removed` lists removed tokens. Removing a connection is `DELETE /api/plaid/items` with `{"item_id": n}` (`removeItem` in `lib/sync.ts`, queued like a sync): `/item/remove` at Plaid first, then the item, its accounts and their transactions, investment transactions and balance snapshots in one transaction; budgets, recurring rules and merchant rules stay. If Plaid refuses it answers 502 and deletes nothing (without the token the item could never be removed there), except for `GONE_ERROR_CODES`, which only delete locally. Dashboard only: no v1 route or MCP tool, and a request carrying a token gets 403. E2E removes on the `first-run` server (the shared fixture item must stay), with the mock's `/__mock/fail` taking a `path` to fail `/item/remove`. A posted transaction arrives under a new Plaid id, so `applySync` carries the pending row's `category_override` over to it. The overview's per-connection control (`app/connection-button.tsx`) is a sync icon normally and turns into a red Reconnect pill (Link update mode) only when `last_error_code` is in `REAUTH_ERROR_CODES` (`lib/plaid-errors.ts`); transient errors just get an amber dot. Its "⋯" opens a Manage sheet whose "Remove connection" leads to a confirm step naming what is deleted, then calls `DELETE /api/plaid/items`.
- **Authorized date:** `transactions.authorized_date` stores Plaid's `authorized_date` (purchase date, nullable); `date` stays the posted date and drives every dashboard/budget/filter. Agents see it as `authorizedDate` on `/api/v1/transactions` and can bucket `/api/v1/spending` (MCP `spending_by_category`) with `date_basis=authorized` (`COALESCE(authorized_date, date)`). Migration 0010 backfilled it by nulling every `items.sync_cursor` so the next sync replays full history — reuse that trick for any future column backfill from `/transactions/sync`.
- **Headless Plaid E2E test:** bypass the Link browser flow with `POST https://sandbox.plaid.com/sandbox/public_token/create` (`institution_id: ins_109508`, `initial_products: ["transactions"]`), then POST the token to `/api/plaid/exchange`. In-browser sandbox creds: `user_good` / `pass_good`. First sync after linking may return 0 added for ~a minute — retry.

- **Dashboard conventions (M3):** pages are async server components (`force-dynamic`) querying Drizzle directly; shared money/category formatting in `lib/format.ts`; charts are hand-rolled (div bars, inline SVG line) — no chart library. Net worth negates `credit`/`loan` account balances (stored as positive amounts owed); snapshots are bucketed by day (timestamps are per-item, not per-run) in the saved time zone (SQLite `'localtime'`, which follows `process.env.TZ`), like `todayISO()`/`daysAgoISO()`; don't mix in `toISOString()` days, which are UTC. Spending/recurring/budget views exclude `TRANSFER%`, `INCOME` and `LOAN_DISBURSEMENTS` categories and credit card payments (`category_detailed = 'LOAN_PAYMENTS_CREDIT_CARD_PAYMENT'`, since the card purchases already count) via `isSpend` in `lib/insights.ts` — moving money between own accounts isn't spend; other loan payments still are. Spend totals (spending, cash flow, budgets, month-so-far) include pending charges and report the pending part separately (`pendingTotal`/`pendingSpending`); recurring detection uses posted rows only. Recurring (issue #44): the pure heuristic in `lib/recurring.ts` only generates *suggestions* (self-check: `npx tsx lib/recurring-check.ts`); user-confirmed/dismissed `recurring_rules` rows are the truth — /recurring shows questionnaire cards for unreviewed suggestions and computes totals/next-expected from confirmed rules only (`partitionSeries`). Cancellation = DELETE (a still-charging series just resurfaces as a suggestion); upgrade path is Plaid's recurring-transactions product. Budgets and recurring writes go through `/api/budgets` and `/api/recurring` only (validated — the agent trust boundary). Category relabels: `transactions.category` is the *effective* label (`category_override` ?? `category_rules` merchant rule ?? `plaid_category`), materialized so every reader stays unchanged; sync recomputes it with `coalesce(category_override, …)`, and writes go through `/api/transactions/category` only (`lib/categories.ts` holds the allowed Plaid primaries and the JS-side merchant key — SQLite `lower()` is ASCII-only). Responsive convention (M8): mobile-first — base Tailwind classes target ~375px, `sm:` restores the desktop look; wide tables get an `overflow-x-auto` wrapper, except where the phone needs the last column in view (Transactions renders a day-grouped list below `sm:` and the table from `sm:`; filters fold behind `app/transactions/phone-filters.tsx`). Phone navigation (`app/nav.tsx`) is a glass tab bar at the bottom edge with the first four `LINKS` plus a More sheet for the rest; `Page` pads for it and for the safe areas (`viewport-fit=cover`). Destructive actions sit inside an Edit sheet or form (budgets, recurring), not as a red button per row.


- **TypeScript 6/7 split (2026-10-31):** TS 7 ships no compiler API, and typescript-eslint (pulled in by `eslint-config-next`) and Next's build type check need one. So `typescript` is aliased to `npm:@typescript/typescript6` (the TS 6 API, `tsc6`) and TS 7 lives under `@typescript/native` (`npx tsc` runs 7). Lint and `next build` use 6, CI's `npx tsc --noEmit` uses 7. Dependabot ignores `typescript` majors. Undo the split (plain `typescript@^7`) once typescript-eslint supports TS 7.1+ (typescript-eslint#10940).

- **Install/update/uninstall (2026-11-02):** `delta.sh install|phone|update|uninstall|backup` wraps the Docker steps in `docs/updating.md`/`docs/uninstalling.md`; uninstall runs `npm run unlink` (`/item/remove` on every item, since Plaid bills per item until removed). The header's Update pill (`app/update-pill.tsx`, `lib/update-check.ts`) compares the build's `DELTA_COMMIT` (baked by `next.config.ts`: build arg in Docker, `git rev-parse` otherwise) with the latest GitHub release via the compare API (not `main`, which moves for Dependabot bumps and docs; a main build past the release shows nothing), non-blocking, 12h cache, `DELTA_UPDATE_CHECK=off` disables (e2e does). It only copies the command: running it from the app would need the Docker socket in a no-login app.

Never return the secret; the env can't flip once an item is linked. `home-server/compose.yaml` is the no-.env stack for Portainer/CasaOS (x-casaos metadata)/Dockge/Synology/Unraid/TrueNAS (`one-click/compose.yaml` is a symlink to it, so Portainer stacks created from the old path keep updating): published image, port on all interfaces, `DELTA_ALLOWED_NETWORKS` = private ranges, `DELTA_INSTALL=stack` (Update pill links to the panel steps instead of copying `./delta.sh update`). `docker-compose.yml`'s `.env` is optional. E2E runs a second keyless server (`first-run` project, port 3101). Guide: `docs/home-server.md` (the docs site redirects the old `/docs/one-click-install`, which older Update pills link to). Wording rule: describe install options by where you install ("Home server app", "Terminal"), not "one-click"/"one-command". Needs the GHCR image public.
- **Homebrew (no Docker):** `scripts/delta.mjs` is the native CLI (`delta start|open|phone|local|token|backup|unlink`); `start` runs `scripts/start.mjs` with `DELTA_HOSTNAME` (→ `next start -H`, default 127.0.0.1), `DELTA_JOBS=on`, data and `delta.env` in `DELTA_HOME`. The formula (`homebrew/Formula/delta.rb`, source of the `zeapsu/homebrew-tap` repo; its `bump.yml` follows the latest release hourly) builds a release tarball with `node@24`, sets `DELTA_INSTALL=brew` and `DELTA_COMMIT=v<version>`, and the Update pill copies `delta backup && brew upgrade delta && brew services restart delta`. Native installs see real client addresses, so the default `DELTA_ALLOWED_NETWORKS` works. Guide: `docs/homebrew.md`.
- **Releases:** cut with the `release` workflow (`workflow_dispatch`: `version`, `ref`, optional `notes`), which creates the `v<version>` tag + GitHub release via the API and dispatches `docker.yml` on the tag (GITHUB_TOKEN-made tags trigger nothing), so GHCR gets `:<version>`. Cloud agents can't push tags (their git proxy allows only their branch), so they run it through the GitHub MCP. No image assets on releases.
- **README screenshots:** `npm run build && npm run screenshots` (`scripts/screenshots.mjs`) runs the build on a fresh `e2e/.tmp/demo.db` against the mock Plaid with `PLAID_MOCK_DEMO=1` (synthetic seven-month fixture, invented merchants), seeds budgets and a balance history, and writes `docs/img/` (overview light/dark, spending, `social-preview.png` for GitHub's Settings → Social preview). Never screenshot the Jetson: it holds real data. Set `CHROMIUM_PATH` if Playwright's bundled browser is missing.
- **Backups:** `npm run backup` (better-sqlite3 online backup → `backups/`, keeps 7). The database holds the Plaid access tokens, so `db/index.ts` makes it and its `-wal`/`-shm` files owner-only (0600) on open and the backup script does the same for backups, old ones included; a backups folder with the setgid bit is a deliberate share (the Jetson's: the container writes as uid 1000, `zeapsu` reads through the folder's group for the Mac's rsync pull), so files there get 0640. `db/check.ts` and the CI image job assert the modes.

- **Deployment conventions (M6):** systemd units live in `deploy/` — `delta.service` (the app), `delta-backup` (daily backup timer), `delta-sync` (6h Plaid sync timer) — installed via `sudo deploy/install.sh` on the Jetson; `sudo deploy/stop.sh` disables everything, `sudo deploy/uninstall.sh` removes the units (repo/.env/DB untouched). App runs as `zeapsu`, `next start -H <tailscale-ip>` (100.116.56.85) — binding to the tailscale interface is what closes the `x-forwarded-for` spoofing ceiling noted in `lib/tailnet.ts`. `WorkingDirectory` is the repo root because `./delta.db` and `./drizzle` defaults are cwd-relative. Node comes from nvm, so units use absolute paths. The Jetson `.env` additionally sets `DATABASE_PATH` (absolute) and `DELTA_URL` (tailscale IP — localhost is unreachable once bound to the tailscale interface). The tailnet is the trust boundary.
- **Docker / self-hosting (M10, #74):** `Dockerfile` (multi-stage, `node:24-bookworm-slim`, prod deps only, so `tsx` is a runtime dependency for `npm run token`) + `docker-compose.yml` (`delta` app + `jobs`, which runs `scripts/jobs.mjs`, the in-container replacement for the sync/backup timers, sharing `delta`'s network namespace so its requests arrive on loopback). Data in the `/data` volume. `instrumentation.ts` applies migrations at server start and logs the Plaid first-run check (`lib/plaid-config.ts`, also on the welcome page). The API guard's networks are `DELTA_ALLOWED_NETWORKS` (IPv4 CIDRs, default `100.64.0.0/10`, loopback always). `DELTA_PUBLIC_MCP=1` exempts exactly `/api/v1/mcp` (token still required; `publicMcp()` in `lib/api-auth.ts`) for internet-hosted agents reached through a path-scoped Tailscale Funnel; Funnel overwrites X-Forwarded-For, so without it they get 403. Compose publishes on `DELTA_BIND` (default 127.0.0.1); pages have no guard, so the bind is what keeps them private. Gotcha: a port published on 127.0.0.1 reaches the container from the bridge gateway (172.17.0.1, verified), and Docker Desktop always rewrites the source, so `delta.sh` sets `DELTA_ALLOWED_NETWORKS=0.0.0.0/0` for those binds. `delta.sh install` starts a Mac on 127.0.0.1 and opens the browser; `./delta.sh phone` moves it onto the Tailscale IP (Settings → Use on your phone shows the steps). Gotcha (found migrating the Jetson, 2026-11-02): on Linux + Tailscale, port publishing can NAT tailnet clients to a Docker-internal source address, so the API guard refuses them ("Could not start Plaid Link"); `docker-compose.tailscale.yml` (enabled via `COMPOSE_FILE` in `.env`) switches to `network_mode: host` + `next start -H $DELTA_BIND`, and points `jobs` at the Tailscale IP since the app no longer listens on loopback. `.github/workflows/docker.yml` pushes amd64+arm64 to `ghcr.io/<owner>/delta`, each built natively (arm64 on `ubuntu-24.04-arm`, free only on public repos, so a private repo falls back to QEMU) and pushed by digest, then joined into one tag by the `merge` job. User guide: `docs/self-hosting.md`. `deploy/` stays the Jetson's bare-metal path.
- **Production cutover conventions (M7):** the Jetson runs Plaid **production** since 2026-07-09 — real financial data. Local development stays sandbox (`PLAID_ENV` defaults to `sandbox`; the local `delta.db` is sandbox data). The pre-cutover sandbox DB is preserved on the Jetson as `delta-sandbox-fixture.db` next to the live DB. Off-device backups: the user's Mac pulls the Jetson's `backups/` daily via launchd (`deploy/mac/install.sh`; rsync-over-ssh into `~/Backups/delta/`, 60-day retention). The backup script flips each copy to non-WAL journal mode — `sqlite3 -readonly` cannot open a WAL db without its `-shm` file. Sync-health gotchas (issue #34): journald on the Jetson is volatile with ~minutes of retention — an empty `journalctl -u delta-sync.service` does NOT mean the timer didn't fire; check the DB (`transactions` count / `MAX(date)`) instead. Investment/brokerage items legitimately show 0 rows in `transactions` and no cursor — `/transactions/sync` doesn't cover investment activity; it now syncs separately via date-window `/investments/transactions/get` into `investment_transactions` (issue #37 done). Items lacking investments consent (anything linked before investments became an optional product on 2026-07-09, e.g. the Fidelity item) log-skip with `ADDITIONAL_CONSENT_REQUIRED`; `/investments` detects them via `/item/get` (`lib/investments.ts`) and offers a "Grant investments access" button — Link update mode with `additional_consented_products` (`{item_id, investments: true}` on `/api/plaid/link-token`), no re-link needed. Deploying code to the Jetson requires `git pull` + `npm run build` + `sudo systemctl restart delta.service` — a pull alone leaves the old build serving.
- **Charts conventions (M9):** Charts use **recharts** (first UI dep — post-MVP, UI deps are acceptable on merit) as `"use client"` islands in `app/charts.tsx` with fixed-height wrappers (ResponsiveContainer is client-only); the home sparkline stays hand-rolled server SVG. Palette = chart CSS vars in `app/globals.css` (light/dark via `prefers-color-scheme`, CVD-validated). Gotcha: `var()` is invalid inside SVG fill/stroke *presentation attributes* (renders black, no error) — recharts sets colors as attributes, so `globals.css` carries attribute-selector rules (`[fill="var(--chart-1)"] { fill: var(--chart-1); }`) that re-assert them as CSS; keep that block in sync when adding chart vars.
- **Design system (liquid glass, neutral):** tokens + materials live in `app/globals.css`; chrome (nav, cards, controls) is black/white/gray; color carries meaning — category identity (`--chart-1..8`: `categoryColor` in `lib/colors.ts` pins one hue per common category so it never changes month to month and the big ones stay off the status green/red; unpinned categories take the free slots; shared by spending/overview/transactions and mirrored by hand in the landing mock), money in/out (`--chart-in`/`--chart-out`, lightness-separated for red-green CVD) and status (`--positive`/`--negative`/`--warning`; budgets are ink while on track, amber from 80%, red when over via `budgetTone`, and history bars are neutral with red only for months over budget). Two layers, per Apple's Liquid Glass guidance: content sits on `.surface` cards (translucent, no backdrop blur), and only the floating functional layer uses `.glass` (backdrop blur + top-edge highlight: nav pill, chart tooltips, month switcher) — never glass on glass. The nav pill adds Chromium-only edge refraction (`app/refraction.tsx` SVG filter via `backdrop-filter: url()`, opted in by `nav.tsx` setting `<html data-refraction>`; Safari/Firefox would drop the backdrop entirely, so they keep the blur). `prefers-reduced-transparency`, `prefers-contrast: more`, `forced-colors` and no-`backdrop-filter` fallbacks are in the same file. Controls use `.btn` / `.btn-primary` / `.btn-sm` / `.btn-danger` and `.field` (already ≥16px on mobile). Page scaffolding (`Page`, `Card`, `Stat`, `Money` for headline amounts with receding cents, `Change`, `Meter`, `Empty`, `Pager`) is in `app/ui.tsx`; shared dashboard queries (cash flow, category totals, budget progress, recurring pipeline) in `lib/insights.ts`; month/date helpers in `lib/months.ts`. Gradient `<stop>`s also need the attribute-selector rule (`[stop-color="var(--chart-ink)"]`).
- **API guard:** root `proxy.ts` runs on every `/api/*` request — the tailnet `allowed()` check plus `crossSiteWrite()` (refuses non-GET requests a browser sent from another origin, via `Sec-Fetch-Site`/`Origin`; curl and agents send neither and pass). `knownHost()` (same file) is the DNS rebinding guard for pages and non-v1 routes: the `Host` (and `X-Forwarded-Host`) must be an IP, `localhost`, a single-label name, a `.local`/`.lan`/`.home`/`.home.arpa`/`.internal`/`.ts.net` name, `DELTA_URL`'s host or listed in `DELTA_ALLOWED_HOSTS` (`*` disables), else 403 with the fix in the body; `/api/v1` is exempt because a web page can't supply its token. New API routes are covered automatically: the matcher lists `/api/:path*` on its own, because the page pattern skips paths ending in an extension and a dynamic route also answers `/api/tokens/1.0` (found 2026-11-11; `e2e/api.spec.ts` and `login.spec.ts` now walk `app/api` and assert every route, with and without an extension, is behind the guard and the password). `next.config.ts` sends `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff` and `Referrer-Policy: same-origin` on every response. Self-check: `npx tsx lib/tailnet-check.ts`.
- **Agent API (M10, #72):** `/api/v1/*` is the token-authenticated API agents (Felix, the future MCP server #73) use instead of the DB file. `proxy.ts` (Node runtime, so it can read the DB) requires `Authorization: Bearer dlt_…` there: GET/HEAD need `read` scope, writes need `write` (`lib/api-auth.ts` pure policy + `api-auth-check.ts`; `lib/api-tokens.ts` DB side). Older routes still serve the dashboard and sync timer without a token, but a token sent to them is validated. Tokens: 256-bit random, only the sha256 stored in `api_tokens`; manage with `npm run token -- create <name> [--scope read|write] | list | revoke <id>` on the host with the DB. or in the browser on Settings → Agents (`/api/tokens`, which refuses any request carrying a token so agents can't mint tokens; configs come from `lib/agent-config.ts`, shared with the CLI). Read routes reuse `lib/insights.ts`/`lib/networth-data.ts` via `readRoute()` (`lib/api-params.ts`, bad params → 400); v1 writes re-export the `/api/budgets`, `/api/recurring` and `/api/transactions/category` handlers (MCP `set_transaction_category` / `reset_transaction_category`). `GET /api/v1` self-describes. Never select `items.access_token`/`sync_cursor` in a v1 route. Sync runs are serialized in `lib/sync.ts` (an overlapping timer + button `syncAll()` shares one full run; `syncOne()` waits its turn).
- **MCP server (M10, #73):** `POST /api/v1/mcp` is a stateless Streamable HTTP MCP endpoint (JSON responses, no SSE/sessions, GET → 405), hand-rolled with no SDK. `lib/mcp.ts` is the pure protocol + tool layer (self-check `lib/mcp-check.ts`); `app/api/v1/mcp/route.ts` hands it an `api()` that calls the v1 route handlers in-process — the MCP layer never touches the DB, so tools get exactly the API's validation and numbers. Proxy requires only `read` scope for POSTs there (`MCP_PATH` in `lib/api-auth.ts`); write tools are hidden from `tools/list` and refused per call for read tokens. Tools return **dollars** (cent keys listed per tool, since `total` is a row count on paged endpoints) plus an `as_of` block (stale after 3 days, failed connections) and carry Delta's conventions, analysis method, privacy and advice rules in `INSTRUCTIONS`/descriptions. `npm run token -- create` loads `.env` (`process.loadEnvFile`) and prints paste-ready MCP configs pointed at `DELTA_URL`. When adding a v1 route an agent should use, add a tool (and its route to `ROUTES`). Analysis thresholds (category spike %/$ vs an N-month baseline, trend months, budget heads-up %) are user settings: pure defaults/validation in `lib/analysis.ts` (self-check `analysis-check.ts`; defaults checked against Yodlee's spending-exceeded-average insight), stored as JSON in the `settings` table (`lib/settings.ts`), edited on `/settings` via `PUT /api/settings`, read by agents at `GET /api/v1/settings`, and filled into the MCP instructions at `initialize` (`{{ANALYSIS}}` placeholder). The page leads with three presets (Relaxed / Balanced = defaults / Watchful, `ANALYSIS_PRESETS`) and hides the numbers behind "Customize"; until saved, Overview shows a "Choose how closely your agent watches spending" prompt. The dashboard's own 80% budget tone is still fixed.

- **Profile + time zone:** `settings` row `profile` = `{name, timeZone}` (pure parsing `lib/profile.ts` + `profile-check.ts`), edited on Settings → You and the welcome page via `PUT /api/settings/profile`. The welcome page (`app/welcome.tsx`, shown until a bank is linked) is one card per step: "Hi, <name>" (underline-only field), Plaid keys (the `/setup` form inline), connect a bank, with Back; after linking, Overview's Getting started takes over. Every date helper uses the process's local time, so `applyTimeZone()` sets `process.env.TZ` (Node re-reads it on assignment) at startup (`instrumentation.ts`) and on save; the saved zone wins over `.env` `TZ`, which `delta.sh install` copies from the host. Docker defaults to UTC, which made evenings read as tomorrow. E2E saves `UTC` only: the fixture is dated in UTC.
- **Web UI password (opt-in):** Settings → Password stores `{hash (scrypt), secret}` as the `login` settings row (`lib/login.ts` pure + `login-check.ts`, `lib/login-store.ts` DB side, no `server-only` so the CLI can use it). `proxy.ts` now matches every path but build assets/files: with a password set, pages redirect to `/login?next=` and non-v1 `/api/*` answers 401 without the `delta_session` cookie (`<expiry>.<HMAC>`, 30 days, HttpOnly, Lax, Secure over https). `gate()` keeps `/api/v1` on tokens only (a bearer never stands in for the cookie on dashboard routes) and leaves `/login`, `/api/auth/*` and the sync timer's `POST /api/plaid/sync|refresh` open. Changing the password rotates the secret (logs out other devices), and so does logging out (`POST /api/auth/logout` from a valid session; the cookie is stateless, so one session can't be ended alone and the button reads "Log out everywhere"); change/remove need the current password and refuse agents. Login tries are throttled per address (10 per 15 min) and overall (50 per 15 min, since the address is a spoofable `X-Forwarded-For`); `safeNext()` allows printable-ASCII same-site paths only (browsers strip tabs/newlines, so `/\t/evil.com` was an open redirect). Forgot it: `npm run password -- reset` / `./delta.sh reset-password`. The nav hides on `/login`. E2E: `login.spec.ts` runs last (the `login` project depends on all others) and turns it off again.

## Priorities

- **Velocity and cost-efficiency first.** MVP = a functioning product. UI/UX is secondary but must be functional and reasonably polished.
- Prefer the simplest working solution; avoid speculative abstractions and premature infrastructure.

## Development Workflow

Default to an **orchestrator pattern**: the main session plans and coordinates, delegating implementation tasks to subagents with explicit model choices — cheaper/faster models (e.g. Haiku/Sonnet) for mechanical or well-specified work, stronger models only where the task demands it.

**Session start:**
1. `git log --oneline -20` and `gh pr list` — see where the last session left off and confirm it closed cleanly. If an orphaned branch/PR exists, resume or finish it before starting new work.
2. `gh issue list --milestone "<next open milestone>"` — the current milestone's open issues are the session's scope.
3. Create the milestone branch (e.g. `m2-plaid-integration`) and open a draft PR early so progress is visible from the first commit.
4. Plan the session against those issues before delegating implementation, per the orchestrator pattern.

**Cadence: one milestone per session, one PR per milestone.** Work each session on a branch for the current milestone. Commit frequently with descriptive messages — rich git history is how context is preserved across sessions. At the end of the session, run the **close skill**, which commits remaining work, merges the PR, and ends the session.
